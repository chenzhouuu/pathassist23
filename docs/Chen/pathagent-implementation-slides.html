PART A · 02 / 25 · Why this is hard

A single slide is a gigapixel haystack.

Pathologists sign out diagnoses by scanning enormous digitized glass slides. A WSI is often 100,000 × 100,000 px+ — the equivalent of thousands of high-res photos — yet the diagnostic clue may be a few cells. A general chatbot can't "see" a gigapixel image; it needs help knowing where to look.

PART A · 03 / 25 · The platform

A white-label platform that puts AI beside the microscope.

PathAssist (Impart DX) is a browser WSI viewer built on the open-source Digital Slide Archive / Girder 5, with an embedded AI layer — multi-tenant and white-label (one backend, many branded labs), lymphoma/DLBCL-first with broader oncology ambitions.

PART A · 04 / 25 · The idea

An agent that co-navigates the slide — and shows its work.

Instead of a single black-box answer, PathAgent works like a pathologist at the scope: it triages the slide, moves the viewport to the regions that matter, describes what it sees, proposes a diagnosis, then verifies itself against medical knowledge and independent classifiers before committing — streaming every step into the viewer.

Navigates

Drives the live OpenSeadragon viewer to the evidence — low-mag survey, then high-mag dives.

Verifies

Dual verification → a calibrated confidence badge with citations, not a vibe.

Grounded

Every claim tied to a visible region + source; each run auto-saves a provenance annotation.

It doesn't just answer — it co-navigates the slide with the pathologist and shows its evidence in the viewer.

PART B · 06 / 25 · Architecture · composition

Three systems, each doing what it's best at

PathAgent invents no new backbone. It composes three mature systems — a live viewer, a cached feature backbone, and a verification layer — then adds the one thing none of them had alone: an agent that drives the actual microscope.

PathAssist · head / data plane

Multi-tenant DSA / Girder 5 viewer — React 18 + OpenSeadragon. Alone: a viewer, no reasoning.

Trident · feature backbone

WSI → seg → coords → CONCH / UNI embeddings, cached. Alone: features, no trust or narrative.

WSI-Agents · trust layer

Dual verification → a scored, cited summary. Alone: built for offline benchmarks.

+ PathFinder · navigation loop SlideChat · deferred Patho-Bench · M5 eval

The fusion is the novelty  M0–M4 shipped

WSI-Agents and PathFinder were built for offline benchmarks; PathAssist is a live viewer. We fused them and let the agent drive the actual viewport — now running end-to-end.

PART B · 09 / 25 · Navigation

Query-conditioned concept similarity — training-free, now real

The question is embedded with CONCH's text tower and cosined against every cached patch embedding, so attention follows the actual question. The sampler balances exploitation (top-similarity hotspots) with coverage (survey→dive) — zero-shot, ~free from the cache, and strictly advisory: where to look, never the answer.

Advisory, not diagnostic

Concept-similarity is guidance for where to look — never the diagnosis itself.

PART B · 10 / 25 · Verification

Two independent checks — with a calibrated confidence

The low φ_k is a feature, not a bug

The small local reasoner found the answer only weakly supported by short seed-KB snippets and pulled confidence down — verification being appropriately skeptical. Richer KB + stronger reasoner + φ-weight tuning is exactly the M5 calibration work.

  • Abstention is designed in. Non-H&E or no tissue → low confidence.
  • Disagreement lowers trust. Classifier vs LLM conflict pulls φ_total down.
  • Answer-first, verify-streaming. The badge updates live as φ scores arrive.

The bug only the live browser could catch.

The SSE reader split frames on \n\n, but sse-starlette delimits events with \r\n\r\n — so no frame ever parsed and the trace came back empty. A direct curl test missed it (it bypassed the JS parser); the live end-to-end run surfaced it. Fix: strip \r before framing.

v1 = pause-only take-control + manual save. Auto-persist every run and the M3b task chips are deferred, documented.

PART C · 18 / 25 · Data contract

Everything speaks level-0 pixels — proven by co-navigation.

The trickiest part of an in-viewer agent is geometry. The contract: all coordinates crossing /api/agent — ROI, navigate regions, heatmap extents, attention coords — are level-0 (base) image pixels. Backend owns patch↔px0; frontend owns px0↔viewport.

  • Derive downsample / magnification from Trident attrs — slides vary 40× vs 20×; never hardcode.
  • Build the raster on the full grid at Trident's exact origin, or the heatmap smears by a patch.
  • The X-Level0-* headers must be CORS-exposed or the overlay silently breaks — a real M3 fix.
  • The M3 heatmap extent and M4 co-navigation moving the viewport to the right regions prove the contract holds end-to-end.

PART D · 21 / 25 · Evaluation · M5

The merge is testable — and the tests are the contribution.

M5 measures the multi-agent layer against single-model baselines across four axes; the ablation grid is the core claim — navigation and verification each add value, and interact when merged. The real M3 observation (φk 0.0 → φtotal 0.40 on a correct answer) is exactly what the calibration axis exists to measure.

Axis 1 · Task accuracy

Patho-Bench (42 tasks) + SlideBench-VQA (TCGA / BCNB) + WSI-Bench. 42 tasks

Axis 2 · Trust & calibration

φk factuality (human-audited), reliability diagram / ECE, citation validity, abstention P/R — motivated by the real φk 0.0 run. ECE

Axis 3 · Navigation quality

Region hit-rate vs CAMELYON16 pixel masks (IoU / recall) + efficiency (regions to reach the answer). CAMELYON16

Axis 4 · Human factors

Reader study, pathologist ± copilot: accuracy, time-to-diagnosis, automation bias. needs IRB · later

Provenance annotations double as versioned eval records — model + KB + prompt captured per run, so the eval set builds itself as reproducible records.
