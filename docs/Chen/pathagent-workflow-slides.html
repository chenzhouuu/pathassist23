Whole-Slide AI Copilot · End-to-End Workflow

A gigapixel slide goes in.
A verified, cited, navigable diagnosis comes out.

PathAgent is an in-viewer, multi-agent pathology copilot built on the PathAssist / Digital Slide Archive stack. It doesn't just answer a question about a whole-slide image — it co-navigates the slide with the pathologist, shows where it looked, and scores how much to trust the answer. This deck traces one slide from pixels to sign-out, step by step: what runs, which model does it, and what comes out.

The mental model — 02

Everything is two phases: prepare the slide once, then ask it questions

The expensive, GPU-bound work happens once per slide, in the background, and is cached. Every question after that is a fast, streamed agent loop over those cached features. Nothing about answering re-reads the gigapixel pixels.

A Precompute — background, minutes

Triggered when the case is opened. Turns the raw slide into a reusable feature cache so the agent never touches raw pixels at query time.

segmentationpatch coords CONCH featuresconsensusclassifier
POST /cases/{itemId}/preprocess → RQ job → ready

B Query — interactive, streamed

One question runs a LangGraph multi-agent loop that navigates the slide, gathers evidence, proposes a diagnosis, and verifies it — emitting typed events live over SSE.

routetriagenavigate ⇄ describe diagnoseverifyfinal
POST /query → Server-Sent Events → the panel
Design principle — answer-first, verify-streaming: the preliminary diagnosis renders immediately; the trust scores stream in behind it and update the confidence badge live.

The cast — 04

#The cache key is the whole caching story

formulaitemId-sha256(payload)[:12]
payloadpipeline version + itemId + backbone spec + consensus spec + slidechat flag
exampleBRACS_1648.svs-53eb9c0bf957
  • Idempotent — same params → same key → the run is reused, never recomputed.
  • A case already ready short-circuits: the API returns jobId:"cached" with no new job.
  • Bumping PIPELINE_VERSION invalidates every stale cache at once.
Every path segment (itemId, encoder, cacheKey) is validated against traversal (/ \ ..) before it ever touches the filesystem.
Stage 1 · resolve & fetch — 07

Find the real .svs — local first, Girder second

The worker turns an abstract itemId into a file on disk. Local disk is tried first for speed; otherwise the gigapixel slide is streamed from the Girder / DSA server.

1Local resolver

  • Looks under a configured slides_root by item id + WSI extension.
  • Matches a Girder file to a local one by exact name and exact byte-size — never name alone (filenames aren't unique across patients).
  • Rejects glob metacharacters to prevent cross-case disclosure.

2Girder download

  • Lists /item/{id}/files, picks the largest WSI file.
  • Streams /file/{id}/download in 1 MiB chunks to a .part temp, then atomic rename — a mid-stream failure never leaves a truncated slide.
  • Filename sanitized to a basename before any disk write.
Verified live: a 1.3 GB slide pulled anonymously from the public DSA collection, then processed end-to-end. Output → a local file path handed to Trident.
Stage 2 · Trident backbone — 08

B Phase B

The merged agent loop

A single question streams through a LangGraph graph that fuses two research designs — PathFinder's clinical navigation loop and WSI-Agents' dual verification — over the cached features.

routerroute→ triagebudget→ navigatewhere to look ⇄ describefindings→ diagnosecandidates
↑ navigate ⇄ describe loops until the exploration budget is spent
diagnose→ icv · φLfact · φKconsensus · φC →summaryverify + final
the three verifiers run in parallel, then converge on the sign-out
The wire — 12

One question → a stream of typed events

POST /query opens a Server-Sent-Events stream. Each graph node emits one typed event; the panel renders each as it arrives. This is the exact contract the frontend consumes.

routetask = Diagnosis · tools = [navigate, classifier, kb, verify]
triagerisk, depth, maxRegions — how deep to explore
navigate{ region(level-0 px), zoom, rationale } — one per region · panel moves the viewer
describe{ region, findings } — loops back to navigate while budget remains
diagnose{ candidates:[{source, answer}] } — preliminary answer renders now
verify{ scores:{phiL,phiK,phiC,phiTotal}, citations }
final{ answer, confidence, heatmapTaskId, trail, citations }
erroron any exception the stream ends with one terminal error event — never a bare 500
Ordering: route → triage → (navigate → describe)⁺ → diagnose → verify → final. The verify and final events are emitted together, so the answer and its trust scores land back-to-back.
Nodes 1–2 · route & triage — 13

First: what task, and how hard to look

1Router · deterministic

Decides the task and which tools the run will use. In v1 this is rule-based, not an LLM call — the scope is fixed to Diagnosis.

taskDiagnosis
toolsnavigate · classifier · kb · verify
emitsroute

2Triage · deterministic

A fast risk read that sets the exploration budget — the cap on how many regions the navigate⇄describe loop may visit before it must decide.

classifier presentsuspicious · deep → up to 8 regions
no classifieruncertain · moderate → ≤ 4 regions
emitstriage
The budget is the loop's real bound (a hard graph recursion limit backstops it). Higher risk buys more looks — mirroring real sign-out, where a suspicious slide earns more scrutiny.
Node 3 · navigate — 14

Where to look — the question paints the slide

The importance map is query-conditioned: the pathologist's question is embedded by CONCH's text tower and cosine-matched against every cached patch embedding. Navigation follows the actual question — training-free, essentially free from the cache.

σThe scoring

text = CONCH.encode([question, *concepts])
sim  = patch_feats · textᵀ
score = 0.5·question_sim + 0.5·best_concept_sim

Six diagnostic concepts (IDC, ILC single-file, tumor-in-stroma, high grade, DCIS, benign) anchor the map so it means something even for a vague question.

◎Picking regions — survey then dive

  • Top-6 hotspots by score — exploitation.
  • Coverage sampler over a 4×4 grid — so it doesn't fixate on one corner.
  • Each region carries a rationale ("matches: invasive lobular…") and a zoom.

Emits one navigate event per region → the panel pans/zooms the live viewer there.

Advisory only. Concept-similarity decides where to look — never what the answer is. It's guidance, not a diagnosis.
Nodes 4–5 · describe & diagnose — 15

Gather evidence, then propose candidate answers

4Describe · 1 LLM call / region

The reasoning LLM turns each visited region into a structured finding, then the graph loops back to navigate while the budget holds.

  • Input = region coordinates + concept affinity.
  • v1 reasons from location + signal, not fetched pixels — the true-resolution crop feed is a documented next step.
  • Emits describe per region.

5Diagnose · 1 LLM call

Synthesizes candidate answers from two independent sources, then streams a preliminary answer immediately.

  • Classifier candidate — the BRCA verdict (ILC 70.9%).
  • LLM candidate — the reasoner over the gathered evidence {answer, reasoning}.
  • Emits diagnose with both candidates + a prelim answer.
Two independent answer generators is the point: a foundation-model classifier and a reasoning LLM. Where they agree, confidence rises; where they diverge, the verifier surfaces it.
Node 6 · dual verification — 16

The trust layer — three judges, run in parallel

This is what sets PathAgent apart from a plain chatbot: before the answer is finalized, three independent checks score it. Each writes its own score; a weighted blend becomes the confidence.

φLICV · logic

LLM audits internal consistency — do the gathered findings actually support the diagnosis?

φKFact · KB

LLM rates support against retrieved WHO + PathologyOutlines snippets → returns citations.

φCConsensus

Deterministic: does the answer agree with the BRCA classifier? Agree → its confidence; disagree → capped low + a note.

φ_total = weighted, renormalized over present branches

φL·34
φK·33
φC·33
φΣwtd

A missing branch is excluded, not zeroed. Weights (0.34, 0.33, 0.33).

⚑Abstention is a feature

A weak knowledge match or a classifier disagreement legitimately drags φ_total down — the system is designed to be skeptical and say "uncertain, recommend review" rather than confidently hallucinate.

Node 7 · summary — 17

The sign-out — one answer, with its evidence attached

The summary node folds the scores into a confidence, asks the LLM for a 2–3 sentence attending-style answer, and packages everything the viewer needs to show why.

final event payload

answer    : "…invasive lobular, single-file pattern…"
confidence: round(100 · φΣ)
trail     : [ 8 visited regions · level-0 px ]
citations : [ WHO / PathologyOutlines … ]
heatmapTaskId: → GET /heatmap/{id}

▦The heatmap

The perception step also rendered a jet-colormap importance PNG over the patch lattice, transparent where there's no tissue. Served by /heatmap/{taskId} with X-Level0-* extent headers so the browser can place it pixel-exact over the slide.

Everything crossing the wire — regions, trail, heatmap extent — is in level-0 image pixels. One canonical coordinate space, end to end.

Confidence is color-coded in the panel: ≥ 70 green · ≥ 40 amber · < 40 red — the trust score is impossible to miss.
The reasoner — 18

One local, pluggable LLM does all the thinking

Router and triage are rule-based; consensus is arithmetic. The genuine reasoning — describe, diagnose, the ICV & fact judges, and the final sign-out — is ~N+4 calls to one small LLM per query.

◆As-built

modelGemma-4 / MedGemma (pathology-tuned)
servinglocal Ollama · /chat · single system+user turn
robustnessbrace-matching JSON extractor tolerates fenced / prose-wrapped replies
containmentany LLM failure degrades to a neutral score — never crashes the stream

⇄Pluggable by design

  • Reasoner is a config swap — hosted GPT-4V for de-identified data ↔ self-hosted Qwen2.5-VL for future PHI sites.
  • Why local first: $0 egress, privacy, pathology-tuned — a real HIPAA-friendly wedge.
  • Every LLM call is bounded by a timeout; the budget caps total calls per query.
The design names GPT-4V + SlideChat as the reasoning layer; the running system swaps in a local Gemma without a rewrite — the whole point of keeping the reasoner behind one client interface.
Frontend · M4 — 19

In the viewer — the agent co-navigates with you

The React PathAgent panel consumes the SSE stream and turns it into a live experience: as each navigate event arrives, it pans the real OpenSeadragon viewport to that region — the pathologist watches the agent work.

⤢Co-navigation

Level-0 rect → imageToViewportRectangle → animated fitBounds. The viewer flies to each region.

▦Heatmap overlay

addTiledImage at the level-0 extent, 50% opacity — pans & zooms natively with the slide.

◧Streaming trace

A live timeline of every event; a confidence badge + φL/φK/φC/φΣ bars + clickable citations.

◎Navigation trail

The visited regions, listed and clickable — jump back to any of them.

⏸Pause / take control

Stop the panel from consuming further moves without killing the stream — the pathologist stays in charge.

⤓Save to Girder

Honest boundary — 21

What runs today — and what's deferred, not faked

✓Real & verified on WSIs

  • Trident CONCH backbone + UNI consensus + BRCA-ABMIL classifier
  • Query-conditioned CONCH navigation + importance heatmap
  • Full LangGraph loop with the navigate⇄describe cycle
  • Dual verification φL/φK/φC and the seed KB with citations
  • Local Gemma/MedGemma reasoner · live React panel + co-nav

⋯Deferred / pluggable

  • SlideChat slide-level VQA + TITAN slide-encoder — not on this box
  • Full WHO + PathologyOutlines KB — v1 is a 12-entry seed
  • Pixel-grounded describe — v1 reasons from coords, not fetched crops
  • Hosted GPT-4V reasoner · auto-persist every run · redirect/resume
  • M3b tasks (Morphology / Treatment / Report) · M5 eval
Each deferred piece is a documented seam, not a stub — a config swap or a next milestone, chosen deliberately so v1 runs fully on a local, de-identified path.
